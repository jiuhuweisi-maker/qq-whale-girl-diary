# 189：记忆检索与慢回分项分析

历史资料读取原来把同一批日记放进`entries`和`results`两次，MCP序列化后两份正文都会传给模型。现在只保留`results`一份；来源、稳定身份、时间、私密标记、长记录及分页仍完整。省去的是重复输入，不更改记忆原文、人设、模型或候话安排。

QQ话题检索按当前发言人的稳定账号、当前会话、其他允许来源分阶段查找，所有记录仍须匹配查询，不靠昵称猜人。遍历完整允许快照后才进入较低优先级，不是只给第一页重新排序。游标冻结人物和所有日期文件的边界，跨页新增或回填不会让旧结果重复/遗漏。日期浏览和旧版游标继续兼容。排序仅表示相关性，不证明关系或陈述为真；群私权限不扩大。

新增被动计时工具`integrations/surfcore/analyze-session-timing.mjs`，只统计事件元数据和原始usage数字。区分模型生成/重试、普通工具、候话、原生回合总长和首次发送调用。首次调用不是腾讯送达证明，也不包含QQ收件、8秒合批或排队。Token字段不当作价格，不假定失败重试都收费。以实际安装时间切分的历史样本显示：部分长回合主要在候话，另有供应端错误重试延迟首发；不能把修复前坏图历史算成当前版本表现。

本次保持原模型、8秒合批、5分钟候话、可爱表达和表情资产。没有新增模型调用、真实群/私信或B站测试消息；不更改DSH/SnowLuma版本、ExecStart、QQ容器或生产角色与记忆。长期自然度按平时真实聊天观察。

验证包括31项记忆/计时、40项运行时、30项实际桥解析/HTTP/模型序列化，以及全新初始化和构建。覆盖同名/改名、跨平台同号、长记录分块、跨页追加与回填、隐私范围、旧游标，以及工具输出正文只有一份。自动兼容更新回归补入两组新的记忆检查。

运行时版本标记与公共构建版本对照检查；启动时捕获桥、runtime和两份检索模块的指纹，防止只看磁盘却误称新代码已加载。完成状态以部署后的实际加载与账本复核为准。没有足够新真实事件时，不宣称已经测得长期费用降幅或固定回复速度。

最终已差异部署189，535源文件与四份启动指纹一致。真实只读资料HTTP接口验证排序启用、正文一份；QQ/WS/DSH健康，待处理0、旧uncertain2原样保留。只重载桥三次（初次部署、补正版本证明、补正空人物阶段），未重启DSH或QQ。更新器8项检查通过并纳入新记忆回归。未进行新的真实聊天自然度或费用对照试验。
