# 200 · 带话发群：接话确认漏词修复

主人 11-04 18:10 让她把「@全体成员 / 111 / tmd人都死哪去了」三句带到群里，她回「还是不行，群里这边一条都没落地」。接口记录核对：她 18:11、18:13 的**普通群回复都正常落地**，被拒的只有带原话的群发。

## 根因

桥的发送前证据核对只认一张固定的确认口令清单（199 原有「去吧」「那就去发吧」「能帮我带过去吗」「麻烦把那句话发到群里吧」「能帮我发一下吗」「你现在就可以试试」等）。主人这次说的是：

- 「你试试能不能发了」（18:10:56）
- 「发呀」（18:12:36）

两句都不在清单里 → `ownerGroupEvidence` 返回 null → 接口 `state:not_sent`（没核对到当前的发送意思和原话），一条都没发。另外，「发呀」和带原话的那条之间还隔着一句「我刚群里戳你了」，旧扫描逻辑遇到这类衔接话会直接中止。

工具本身没坏：模型两次都把三句原话一字不差填进 `lines`，messageId 也用的当前消息；卡的是关卡。

## 修复（bridge.js，一处）

1. 把确认口令抽成 `isOwnerGroupConfirm()`，新增两类自然说法：
   - 「你试试能不能发了」「试试能不能发」「试试看能不能发」等验证式接话；
   - 「发呀」「去呀」「发呗」等只有语气的短接话。
2. 往前找带原话的那条时，允许跨过衔接话（会话确认句、「我刚群里戳你了」「我拍了拍你」这类），120 秒时间窗、原话逐字顺序、群语境、否定词拦截等原有保护不变；遇到任何不像衔接话的新内容仍然立刻停手。
