# 206：关系优先加载、记忆健康和耗时费用诊断

确认关系仍保存在原私密文件，每轮12条预算不变。最新发言者、结构化@对象、能按消息编号解析的引用作者优先，保留稳定身份与重名区别。未展开的关系仍可经QQ现有记忆检索工具按昵称/person标记检索；B站journal --query复用相同确认关系读取器。不依据昵称猜账号，不删除未加载关系，不把整份名册塞进每轮提示。

主人后台的GET `/api/whale-status` 新增 `memoryHealth`：人物卡状态、确认偏好是否正常/兜底/异常、兜底原因、关系文件状态和确认数量。只返回状态及计数，不返回私密原文、路径或完整错误。偏好权限故障仍报错，兜底不意味着原偏好已恢复。记忆异常不等于QQ掉线。

主人后台的GET `/api/whale-insights` 只读分析既有原生会话与逐步token账本。它沿用控制台鉴权，不向模型开放，不改预算和候话习惯。扫描在有资源限制的后台线程运行，12秒超时，同键请求合并、结果缓存30秒，避免主线程扫描拖慢聊天。

报告分开提供模型（含重试）、识图工具、其他工具、候话以及首次发送尝试前的耗时。首次发送尝试不等于已送达；未结束或缺失证据明确标记。费用按原配置价目表和去重后的缓存命中/未命中/写入/输出桶折算，仅为估算。缓存与未缓存不等于历史文字与本轮新文字，后者不能精确拆分。不累加重复流式采样或重连事件。

范围最多4个当前QQ会话，各末8回合且仅显示当天；逐步账本最多读取尾部8MB，截断有标记。压缩记录最大16MB，解压最大64MB。B站独立会话、轮换前的旧会话不计入此耗时报告。没有数据就显示缺口，不把零样本说成零费用或零故障。

验证包含32个相关单元、40个既有发送/恢复回归、4个B站实际组装回归及1个工具绑定检查；另检查8个变更运行文件语法。生产记录只在服务器内部分析，导出仅统计；无付费模型测试或真实测试发言。新增2个兼容模块后，部署清单538文件、公共受管源60项。

未改模型、人设、关系事实、偏好原文、图库、概率、8秒合批、5分钟候话、费用或防刷屏保护。长期自然度仍通过日常使用观察。
