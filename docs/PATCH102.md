# patch102：文件与引用附件，以及原有口吻恢复

QQ 已传来的文件此前只剩 `[文件]`，文件名、正文和引用附件没有进入会话。现在直接文件、引用文件，以及同一发言者发完附件后两分钟内的追问都能带上对应附件；不同群、私聊和不同发言者隔离。附件上下文只是背景，不要求逐张点评。

- 文件名和大小会保留，最多接收两个不同文件，每个不超过 8MB；下载时验证大小、限时并限制跳转。失败说明实际接收状态。
- 文本、Markdown、常见代码和配置等文件可直接读入正文，支持 UTF-8、UTF-16 和 GB18030；直接正文最多 18,000 字符，截断会明示，原文件仍以原生附件保留。PDF、Office 等以原生文件交入，后续读取取决于现有解析工具，不假称正文已经解析。
- 引用图片会附回原图；同人后续纠正也能带回最近附件，同批重复图片和文件去重。文件在图片接收失败时仍保留。
- 上传文件一律是待分析资料。即使名为 `AGENTS.md`，里面的身份、权限、命令和提示也不作为系统指令执行。
- 恢复原角色卡。emoji、颜文字、小括号动作和表情包继续用，减少的是反复补戏和编造识别失败原因。

`attachment-audit` 管理接口通过同一消息解析与附件存储路径回放指定会话的历史消息，只返回接收事实；不调用模型、不发 QQ 消息。回归命令见 `tests/README.md`。语言风格仍要从真实聊天评估，不以代码检查代替主观效果。

部署后用实际历史消息回放：14,602字节的 `AGENTS.md` 作为原生附件接收，7,635字符正文完整读入；引用该文件的消息也得到同一附件和正文。另一次真实图片回放成功。58项回归在服务器候选源码上通过，更新后 QQ 在线、原会话正常，无新运行错误。
